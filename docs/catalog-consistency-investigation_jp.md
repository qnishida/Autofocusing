[English](catalog-consistency-investigation_en.md)

ユーザーによると、旧カタログは基本的に公開時点のソースを用いたCPU計算。
旧カタログ、現行CPUの自己項修正前、修正後の3者を区別する。
過去の実装との一致と、同一観測点項を正しく除けているかは別の検証項目となる。

## 今回の修正が変えるもの

48日間の現行677件すべてで、先頭33列は修正前後で完全一致し、行列の34〜38列は
全677行で変わる。したがって旧カタログとの対応付け・推定パラメータ・max/MAD・
採用窓数・bootstrap項目の一致度は、この修正前後で同じ。
監査ドライバは同じ推定結果で両式を評価するため、この一致は構造によるもの。
別途行った修正前後の独立した3日間の実行でも、45件の先頭33列はすべて一致した。
ソース上でも、行列評価は推定の後で行い、検出にフィードバックしない。

対応する旧／現行の選別イベントを固定し、対角パワーの差を
`100 * abs(現行/旧カタログ - 1)` とした中央値：

| 検出成分／対角値 | 件数 | 修正前 | 修正後 |
| --- | ---: | ---: | ---: |
| R / SRR | 164 | 0.0056% | 4.10% |
| T / STT | 35 | 0.0079% | 10.04% |
| U / SUU | 149 | 0.0036% | 2.51% |

修正後の行列は旧カタログの値から離れる。`icmp2` のループ内で
`(icmp1, icmp1)` から差し引く不具合は最初の公開コミット `e551a69` にもあり、
後の高速化で新たに入ったものではない。修正候補は、異なる観測点の組だけを
直接足す独立計算と一致する。これらの行列要素は、旧カタログへの一致だけを
正しさの基準にはできない。

## 開始時の状態が差の一部を説明する

`eval_deri` はプロセス全体の `integ_pre`、`integ_old`、`count_gap` を使う。
起動直後は `integ_pre=0` のため、最初に評価する窓は変動判定を通らない。
状態は区間・日付をまたいで保持され、この動作は最初の公開ソースにもある。
同じ波形でも、指定日から起動する実行と、過去からの連続実行では品質判定の履歴が異なる。

対応した旧／現行で採用窓数が1違う46行は、すべて現行実行の開始日・0時の区間に
集中する（11日付）。うち30行が検出成分の閾値を満たし、旧カタログが常に1窓多い。
前の比較ではこの再起動条件を考慮できていなかった。すべての差を丸めや
後から入った不具合として説明する段階ではない。

同じ現行監査バイナリで3月15〜17日を再計算し、3月16〜17日の前に3月15日を含めた。
アルゴリズム・設定は変更していない。3月16日に旧カタログと共通に対応する17件では：

| 確認項目 | 3月16日開始 | 3月15日開始 |
| --- | ---: | ---: |
| 最初の区間の採用窓数 | 47 | 48（旧カタログも48） |
| 旧カタログと窓数が同じ件数 | 13/17 | 17/17 |
| max/MADの絶対相対差の中央値 | 0.1161% | 0.0926% |
| max/MADの絶対相対差の最大値 | 1.1426% | 0.2135% |
| slownessベクトル差の中央値（s/km） | 6.99e-7 | 4.21e-7 |

3月17日の共通20件の比較統計は変わらない。
これは再起動の影響の実証であり、旧カタログの完全再現や、1日の助走で任意の
長期実行の状態を常に再現できるという保証ではない。
重複する再実行分は48日間の統計に加えていない。

## 過去に修正済みの診断値の不具合

公開時のコードでは `prm_init` が未初期化だった。コミット `393a93e` で入力パラメータ
から初期化しており、当時の[水平2成分の検証記録](horizontal-verification.md)にも記載されている。
この変数を使うのは最適化後の推定変化量の診断値。
旧9・10列が初期p・距離を0として計算したように見えることは、この不具合と整合する。
ただし未初期化変数は常に0になるわけではない。
今回の行列修正とは別の、以前に行った不具合修正である。

## 公開ソースを同一環境で比較

公開版 `149995f` と最初の `e551a69` の `src` ツリーは同一。
公開ソース一式を現在と同じLLVM・ライブラリでビルドした。
互換性調整は明示的なinclude・標準名前空間の指定・macOSのprefetchガード。
FFTWとbootstrap乱数は現行監査と同じ固定設定とした。
未定義の診断値読み出しを避けるため、既知の `prm_init` 修正だけは適用した。
最適化の計算式は変更していない。

3月16日の最初の区間では、4イベントの全38列が現行の修正前出力とバイト単位で一致。
公開版のテストドライバはこの区間の後で終了させ、区間長や計算は維持している。

公開版の比較記録・互換性パッチ。

11月4〜5日を公開ソースで全区間実行した結果も、42イベントの全38列がバイト単位で
現行修正前と一致した。保存済みの現行実行と同じ4スレッドを使用し、旧カタログとの
slowness差があった11月5日のイベントも含む。
入力波形・震源カタログのハッシュは現行実行と一致し、実行前後でも不変。
この条件をそろえた例では公開後の変更による不具合は再現していないが、
全日付・全実行モードの保証ではない。

すべての不具合が存在しないことを保証するものではない。

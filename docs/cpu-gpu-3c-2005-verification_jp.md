# 実データ3成分解析のCPU / Metal整合性

2026-09-17、Apple M4 Maxで検証。2005年3月15–17日の3日間について、
CPUとMetalの60イベントで推定パラメータ、bootstrap出力、スペクトル行列が
カタログの出力桁まで一致した。修正前・修正後の行列式それぞれで比較に合格した。
出力された行列値から計算するエネルギー比にもCPU/GPUの差はなかった。

## 比較条件

- 周波数指定0.1–0.25 Hz。実際は102–256番の155ビン、刻み1/1024 Hz、
  0.099609375–0.25 Hz。
- slowness各座標±0.165 s/km、刻み0.005 s/km、67 × 67グリッド。
  既存の半径マスクを保持。約684–685観測点、3成分。
- 実行バイナリ、波形・震源カタログのハッシュ、開始・終了日、CPU 8スレッド、
  固定乱数、FFTW ESTIMATE | UNALIGNEDを共通化した。
  乱数・FFTの固定は検証専用で、運用バイナリは置換していない。
  開始日も同じにし、[カタログ調査](catalog-consistency-investigation_jp.md)で
  確認した再起動時の内部状態差を避けた。
- Metalを明示指定し、GPU powerはoff。採用した全520窓でCPU/GPUの
  slant stackを比較し、ログでGPU実行を確認した。
- 比較前に定めた許容差はmax・MADの相対値1e-4、収束残差の絶対値1e-12。
  他の列は出力文字列の完全一致を要求した。

## 結果

| 項目 | CPUとMetalの比較 |
|---|---|
| イベント | 両方60件、成分・順序・時刻も同じ |
| 窓ごとのslant stackピーク不一致 | 0 / 520窓 |
| 推定位置・slowness | 出力桁まで一致 |
| bootstrap関連列・スカラーMS_max | 出力桁まで一致 |
| SRR・STT・SUU・Re(SRU)・Im(SRU) | 出力桁まで一致 |
| maxの最大相対差 | 0.0006852% |
| MADの最大相対差 | 0.0017671% |
| max/MADの最大相対差 | 0.0017671% |
| 閾値を通過したR / T / U | 両方28 / 10 / 15件 |

閾値はR/Tがmax/MAD > 7、U（鉛直、V）が > 35。
38列のうち差があったのはmax（2行）とMAD（50行）のみ。
修正前と修正後の行列式それぞれで同じ比較結果となった。
上表の相対差は出力値から100 × abs(GPU − CPU) / abs(CPU)で計算した。

520窓のslant stackの最大スケール誤差は1.96957e-6（0.0001970%）、
相対L2誤差の最大値は4.44972e-6だった。前者の分母は全成分・グリッドの
CPU値の絶対値最大、分子はGPU−CPU差の絶対値最大である。
各セルの相対誤差、SUUの誤差棒、イベント間のばらつきとは異なる。

別途、700観測点・155周波数ビンの合成入力でも検証に合格。
3成分の最大スケール誤差は1.14745232e-5（0.0011475%）、
相対L2誤差9.64068053e-6、ピーク不一致0だった。水平成分の検証も合格した。

## 解釈と適用範囲

Metalが単精度で計算するのは初期のslant stackで、CPUカーネルは倍精度。
3成分モードでは、その後の推定・bootstrap・行列計算は共通のCPU経路を通る。
共通経路にも単精度行列を使う部分があるため、プログラム全体を単精度と倍精度に
切り替えた検証ではない。出力桁での一致は、未出力の中間値のビット一致を意味しない。

行列の自己相関項の減算バグは両バックエンドに共通しており、CPU/GPUの一致は
修正前の式の正しさを意味しない。行列修正によるエネルギー比の変化とGPUの丸め差は
別の問題である。今回の60イベントではCPU/GPUによるエネルギー比のずれは
認められなかったが、CUDA・全期間・全動作モードは検証対象外。
両カーネルを計算する検証モードなので、処理時間は速度比較に使わない。

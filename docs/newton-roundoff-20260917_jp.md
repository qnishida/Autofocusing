# 丸め精度に達したNewton法の終了判定（2026-09-17）

[Newton法の倍精度化の比較](newton-precision-20260917_jp.md)で見つかった終了判定の問題への対応。
選別対象のR候補は従来の解のごく近くに到達したが、浮動小数点演算ではどの試行パワーも
現在値を上回らず、通常の収束条件を調べる前に厳密な `S1 > S0` 判定で失敗していた。

## 限定した追加の終了条件

通常は従来どおり、厳密な改善と既存の収束条件を用いる。
バックトラッキングの全試行が失敗した場合に限り、以下をすべて満たすとき、
現在点を保持して収束扱いにする。

1. 現在のパワーが有限・正であり、すべての試行パワーが有限。
2. 現在点のHessianの4つの固有値が有限で、すべて厳密に負。
3. 既存のパラメータスケールWで表したNewton更新量の最大絶対値が
   `sqrt(eps_double)` ≈ 1.49e-8以下。
   バックトラッキングで縮小した更新量ではなく、元の全更新量を調べる。
4. 2次近似の予想増加量 `-0.5 * g_scaled.dot(step_scaled)` が有限・非負で、
   現在のパワーに対して `8 * eps_double` 以下。
5. 最良の試行パワーと現在値の差の絶対値も、同じ相対許容幅、約1.78e-15以下。

Newton更新による2次のパワー変化が更新量の2乗に対応するため、
更新量には機械精度の平方根、予想増加には機械精度程度の条件を併用する。
係数8は小さな数値的許容幅であり、波形計算全体の厳密な誤差上界ではない。
イベントのmax/MADに合わせた閾値でもなく、今回のデータ以外にも検証の余地は残る。

パワーが同じという理由だけでは、更新量が大きい平坦部まで収束扱いになる。
また、更新量が小さいことだけでは不十分なので、曲率、予想増加、実際の試行パワーも併せて調べる。
パワーの下がった試行点は採用せず、現在のパラメータ・パワーを保持する。
出力する相対パワー変化epsilonはゼロとし、`#NewtonStop reason=roundoff` をログに記録する。
bootstrapの規格化、選別閾値、スペクトル行列、反復上限、通常経路の符号付き距離更新量を使う
既存の収束条件は変更していない。

更新量による終了判定は、例えば
[PETScの収束理由](https://petsc.gitlab.io/petsc/release/manualpages/SNES/SNESConvergedReason/)や
[SciPy BFGSのxrtol](https://docs.scipy.org/doc/scipy-1.15.0/reference/optimize.minimize-bfgs.html)
にもある。ただし、これらは一般的な考え方の参考であり、今回の具体的な閾値や
統計的な誤差評価を保証する文献ではない。

## テストと対象候補の再実行

`tests/newton_roundoff.cpp` は本番の判定関数を24ケースで検査する。
増加が丸めで消える凹2次関数、厳密な停留点、微小な負の丸め差、実測の更新・増加量の範囲、
パワーの単位変更、平坦部の大きな更新、無視できない予想増加、実際のパワー低下、鞍点、
特異な曲率、負の予想増加、非正のパワー、非有限入力を含み、すべて通過した。

3月15日から16日の品質判定履歴を維持した2日間の再実行で、対象のR候補だけを推定した。
対象は2005-03-16 11:51:28開始の窓、初期値 (-0.01,0.09) s/km。
以前の失敗診断時の現在点をそのまま保持し、8回目に収束した。
現在値・最良試行パワーは1.1304596832815571e-6、規格化した全更新量の最大絶対値は
1.0195759592448435e-8、予想相対増加は5.5164869323820266e-16。
失敗した試行点への置き換えはしていない。

## 3日分の全候補での検証結果

選択したCTest 13件はすべて通過。
3月15〜17日のCPU実行と2通りの比較も、記録した検証条件をすべて通過した。
波形・参照カタログのハッシュ、品質判定後の窓、初期seed、Newton法に渡るパラメータは一致。

| 項目 | Newton単精度 | 倍精度・従来のラインサーチ | 倍精度・追加終了条件あり |
|---|---:|---:|---:|
| 初期候補 | 147 | 147 | 147 |
| 出力行 | 143 | 144 | 145 |
| 反復上限 | 3 | 2 | 2 |
| ラインサーチ失敗 | 1 | 1 | 0 |
| 選別R/T/U | 31/10/34 | 30/10/34 | 31/10/34 |

追加条件が働いたのは、診断したR候補1件だけ。
その他の最適化結果と、受理された更新の全記録は、従来のラインサーチを使う倍精度版と同じ。
その版で出力されていた144行は全出力列が完全一致し、復元された行も対象候補だけの再実行と完全一致。
全145行は有限値。残る反復上限の2件を、成功に読み替えてはいない。

Newton単精度版との比較では、元の143候補の出力と、選別された75件がすべて残る。
倍精度化による追加の2件は、いずれも既存の選別閾値未満。
選別75件のslownessベクトルとR/Uはカタログ精度で一致し、地理的位置の最大差は0.01112 km。
T/R・T/Uは、両方の実行で各項が正となる30件で最大相対差3.861e-6（0.0003861%）。
残る45件は、その正のエネルギー比の比較から除外している。

今回のCPU設定で確認した丸めによる欠落は解消した。
すべての日付・周波数帯・slowness格子・GPU入力での同等性まで保証する検証ではない。
型だけを変更した比較で記録したとおり、選別対象外の弱い候補の一部は単精度と倍精度で別の解に収束する。
既知の負の共分散対角要素を持つ選別対象外の2行も残る。
今回の追加終了条件は、それらの推定後の曲率や統計的な誤差評価を修正するものではない。

## 再現方法と状態

```bash
cmake -S . -B build-clang -DCMAKE_EXPORT_COMPILE_COMMANDS=ON
cmake --build build-clang --target test_newton_roundoff --parallel 4
ctest --test-dir build-clang -R '^newton_roundoff_convergence$' --output-on-failure
```

検証バイナリ生成スクリプトと詳細記録は、Git管理外の
`docs/benchmarks/newton-roundoff-20260917/` に保存する。
保存済みの乱数固定Newton倍精度検証環境が必要。生成時には追加した終了条件を本番ソースから
取り除き、先行する本番ソースのSHA-256と一致することを確認する。
全候補用の検証バイナリには、それ以外の数値処理の変更を含めない。
比較する実行は、bootstrap乱数固定、FFTW ESTIMATE | UNALIGNED、3成分、0.1〜0.25 Hz、
±0.165 s/km、dp=0.005 s/km、CPU 8スレッドを共通とする。

実装・回帰テスト・検証記録を `test/peak-search-boundaries` の変更に含める。
main・リモート・インストール済みバイナリは更新していない。

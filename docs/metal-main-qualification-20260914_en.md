# Metal: strict five-day comparison and single-thread performance validation

Detailed benchmark logs and run results are retained locally and are not
distributed in this repository. References to detailed records below describe
those local artifacts.

[Japanese](metal-main-qualification-20260914_jp.md)

On 2026-09-14, `6a7a4bd` and `gpu@7de4c22` were compared, and both requested checks passed.
**Five days of output were byte-identical. With one thread, increases in total time,
Hessian time, and RT-rotation time were within 5% for both the medians and every measured pair.**
Integration into `main` has not been performed.

## 1. Five-day comparison before and after parallelization

2004-01-01 through 05, 16 threads, one run per version.
Warmups were omitted because this check targets accuracy; its timings are not used to
decide whether to adopt the performance change.

- Both versions matched in their 29 events, 20 segments, and 740 accepted windows.
- Accepted-window counts per segment and all 58 initial-candidate log lines (29 events × 2) matched.
- The existing same-backend comparison was used, requiring all 38 columns, including bootstrap columns, to match at output precision.
  Only the convergence residual (column 15) retains its existing `atol=1e-12`.
  **Tolerances were not relaxed to the GPU thresholds of `rtol=1e-3` / `rtol=1e-4`.**
- In fact, the entire event files were byte-identical, including residuals.
- Shared event SHA-256:
  `92893ed8efa1d1a8ee428dd7dda0211f452ce9cdc16d7e797d6a2e87de4b0ec7`.

The machine-readable report
records all trials, binary and event hashes, accepted windows, and initial candidates.
Logs and event files are saved in the same directory.

## 2. Single-thread performance comparison

The input period is 2004-01-01 through 03, matching the existing performance measurements.
With `OMP_NUM_THREADS=1`, one warmup per version was excluded, then five pairs were measured
in alternating order: reference/current, current/reference, reference/current,
current/reference, reference/current.
No other agent-started builds, tests, or benchmarks ran during measurement.
OS caches were not cleared. Total time includes startup, I/O, GPU transfers, synchronization,
and output.

| Metric | Reference median | Current median | Median change | Range of paired changes | Result |
| --- | ---: | ---: | ---: | ---: | --- |
| Total wall time | 36.30185 s | 36.36624 s | +0.177% | +0.022–+0.623% | Pass |
| Hessian | 8.92417 s | 8.97119 s | +0.527% | −0.359–+0.694% | Pass |
| RT rotation | 0.352154 s | 0.362434 s | +2.919% | +1.649–+3.332% | Pass |

Ratios of medians and ratios for each of the five pairs were checked separately.
**For all three metrics, 0/5 pairs exceeded a 5% increase.** These measurements show no
reproducible regression above 5%. Rotation has a small increase of approximately 3%;
these results do not establish zero overhead.
Hessian and rotation use `serial_caller` inclusive time, a separate metric from total wall time.

Total-time ranges were 36.26295–36.47868 s for the reference and 36.32404–36.56101 s for
the current version. The initial-grid median also passed the existing 5% regression check,
changing from 10.27492 to 10.29204 s.
All 12 trials, including warmups, matched in their 20 events, 433 accepted windows, and
initial candidates. All event output, including bootstrap results, was byte-identical.

The `regression` field in the machine-readable report
records medians, changes for each pair, ranges, and the 5% checks.
Logs and event files for every trial are saved in the same directory.
After saving, hashes, event counts, accepted windows, and initial candidates were rechecked
for all 14 event files.

## Reproduction

In each checkout, build using the existing [configuration with Apple Clang](gpu-metal-verification-20260914.md),
then generate a driver with fixed settings using `python3 tests/build_io_probe.py build`.
`BEFORE_PROBE` points to the driver for `6a7a4bd`, and `CURRENT_PROBE` to the driver for `7de4c22`.
Run the following from the current checkout root, using output paths that do not yet exist.

```bash
python3 tests/run_cpu_parallel_events.py \
  "$BEFORE_PROBE" "$CURRENT_PROBE" "$HINET_ROOT" "$CMT_CATALOG" \
  five-day --backend metal --power bootstrap --threads 16 \
  --days 5 --repeats 1 --warmups 0

python3 tests/run_cpu_parallel_events.py \
  "$BEFORE_PROBE" "$CURRENT_PROBE" "$HINET_ROOT" "$CMT_CATALOG" \
  single-thread --backend metal --power bootstrap --threads 1 \
  --days 3 --repeats 5 --warmups 1
```

These commands ran outside the agent sandbox to access the Metal GPU and `/usr/bin/time -l`.
The existing driver strictly checks output equality and records the results in its report.
The 5% checks for Hessian and rotation were aggregated from each trial's `cpu` values.
The comparison formula is `100 * (current / reference - 1)`; the passing condition is
`current <= 1.05 * reference`.

This record completes the two requested checks for horizontal data.
It does not generalize the results to real three-component data, the full archive, or other hardware.
It can be reviewed together with the earlier [16-thread speedup and comparison against the version before CPU optimization](metal-cpu-parallel-performance-20260914_en.md).
Integration into `main` is a separate task after the user reviews the results.

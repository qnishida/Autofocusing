# オプションによるイベントの早期選別（2026-09-17）

現状の注記：以下はNewton法が倍精度だった時点の測定です。
後続の[Newton法の単精度版への復元](newton-fp32-rollback-20260917_jp.md)でも本機能を維持し、
`all` / `selected` の一致を再確認しました。そのCPU検証では全出力143件、選別後75件です。
以下の速度測定は復元前の値であり、復元後の版で同じ速度測定をやり直したものではありません。

`selected` モードを追加しました。初期格子のmax/MADが実験の閾値を通らない候補では、
候補ごとの初期パラメータ探索、Newton推定、bootstrap、スペクトル行列計算を省略します。
デフォルトの `all` は従来の全カタログ出力です。設定方法は
[Scripts/README.md](../Scripts/README.md#compute-only-events-above-maxmad-thresholds)
に記載しました。

ピーク探索、探索範囲、局所コントラスト、候補数上限、水平候補の重複除外は維持します。
Uの推定を省略しても、そのU初期値は水平候補の生成に残します。閾値はデフォルトで
R/Tが > 7、Uが > 35で、成分ごとに変更できます。判定は初期格子の丸め前の値で行うため、
出力の表示丸めによって閾値と同じ値に見える場合があります。指定されたmax/MAD条件を
適用する機能であり、波源の物理的妥当性に関する新しい判定ではありません。

実行ファイルは `--event-selection-info` と起動ログで設定を返します。ランチャーは
`selected` を開始する前に実行ファイルの対応を確認し、設定をmanifestに記録します。
未対応バイナリでは実行用ディレクトリを作成する前に停止します。時間区間・成分ごとに、
初期候補数、省略数、推定数、出力数を記録します。後で条件を変えて再選別したい場合は
全カタログ出力を利用できます。出力列と数値推定法は維持しています。

## 結果の一致確認

登録されたCTest 17件は全て合格しました。新しい閾値境界・非有限入力の検査、
実行ファイルの設定とmanifest、未対応バイナリの拒否に加え、既存のピーク・共分散・
推定・並列化・workspaceを確認しました。既存テストの `/usr/bin/time -l` は、
サンドボックス内ではOS情報にアクセスできず、制限外でそのテストだけ再実行して合格しました。
テスト内容は変更していません。

実データ比較は2005年3月15–17日、CPU・3成分、0.1–0.25 Hz、±0.165 s/km、
dp=0.005 s/km、8スレッドです。検証用コピーでbootstrap乱数とFFTW設定を固定し、
本番コードの乱数・FFT計画の方針は変更していません。

| 項目 | all | selected |
|---|---:|---:|
| 初期候補 | 147 | 147 |
| 推定前に省略 | 0 | 72 |
| 精密推定した候補 | 147 | 75 |
| bootstrap・出力行 | 145 | 75 |
| 選別後 R / T / U | 31 / 10 / 34 | 31 / 10 / 34 |

- デフォルトの145行は、保存済みの従来結果とバイト単位で一致しました。
- `selected` の75行は、全出力から選別した75行と、全38列がバイト単位で一致しました。
  共分散・エネルギー行列も含みます。
- 全147候補の座標、順序、初期max/MADの元の値が両モードで一致しました。
  U由来の水平候補も含みます。
- 採用された波形窓、波形ハッシュ、参照カタログハッシュも一致しています。
- 別途、3月15日の水平2成分だけでも比較し、全7候補・7出力が一致しました。
  この例では元から全件がデフォルト閾値を通るため、高速化ではなく互換性の確認です。

本番bootstrapは時刻依存の乱数のままです。高速化によって標本が変わり得るため、
上の厳密比較には検証用の固定乱数を使っています。閾値付近は境界テストで確認し、
実データの選別対象は表示丸めの曖昧さから十分離れています。

## インストール済み実行ファイルによる3日分の計測

2005年3月15–17日を、実際に使う実行ファイルで計測しました。Apple M4 Max、
Metalによるslant stack、CPUによる推定・bootstrap、OpenMP 12スレッドです。
3成分・帯域・格子・閾値は上記と同じで、`AUTOFOCUSING_GPU_POWER=off` です。
本番の `FFTW_MEASURE` と時刻依存のbootstrap乱数を維持しています。
各モード1回の慣らしを除外し、3組を交互の順序で新しいプロセスとして実行しました。
計測には起動、FFT計画、入出力、計算を含み、workspaceランチャーは含みません。
OSキャッシュは保持しており、未キャッシュのディスク速度ではありません。
ビルドや他のテストは同時実行していません。

| 本番実行の測定値 | all | selected |
|---|---:|---:|
| 3日分の全体時間・中央値 | 97.970秒 | 52.265秒 |
| 3日分の全体時間・範囲 | 97.708–98.040秒 | 52.206–52.443秒 |
| 3日分の中央値を3で割った1日平均 | 32.657秒 | 17.422秒 |
| bootstrap段階の中央値・3日分 | 24.080秒 | 12.665秒 |
| 3回それぞれの出力行数 | 144 / 141 / 143 | 75 / 75 / 75 |
| その出力でmax/MAD条件を通る行数 | 75 / 74 / 75 | 75 / 75 / 75 |

全体で **46.65%短縮、1.874倍の速度**でした。全実行で3ファイルを読み込み、
採用波形窓520、初期候補147は同じです。`selected` は72候補の推定を省略し、
出力はR/T/U = 31/10/34件（日別17・29・29件）でした。入力と実行ファイルの
ハッシュは変わっていません。1日平均はこの3日間の平均であり、各日の個別実測値
ではありません。

**通常実行の再現性に課題が残っています。** `all` の本測定2回目では、他の `all`
実行と全 `selected` 実行に出た、閾値を通るRイベントが1件欠けました。
区間開始 `20050317T115128`、max/MAD ≈ 24.2705、
px/py ≈ −0.00964356/0.0880855 s/kmです。初期候補数は同じで、差はbootstrap前の
推定・出力の採否にあります。閾値付近の候補ではなく、bootstrap乱数だけでは
説明できません。同じ `all` 設定の反復間でも生じるため、選別モードを変更した場合
だけの現象ではありません。その後の
[bootstrap前の再現性調査](pre-bootstrap-repeatability-20260917_jp.md)で、
bootstrap呼び出し0回でも対象の棄却を再現しました。FFT計画による丸め差がNewtonの
終了判定を変えています。本番の終了判定の修正はまだ行っていません。

各組の両方に出たイベントでは、px/pyとスペクトル行列5要素は表示値が一致しました。
通常実行の比較で緯度に最大0.0001°の差があり、bootstrap共分散と平均・標準偏差は
時刻依存の標本によって変わります。したがって、上の固定条件での一致確認は、
通常実行のカタログ全体がビット単位で一致するという保証ではありません。
この計測のために推定法・閾値・FFT計画・乱数の本番方針は変更していません。

別途、検証用実行ファイルで乱数とFFT条件を固定し、同じ3日間をMetalで比較しました。
全出力145行、その選別後75行と `selected` の75行は、**全38列がバイト単位で一致**
しました。丸め前の初期候補147件のログと採用波形窓520も一致し、上記のRイベントも
両方に含まれます。この入力の固定条件では早期選別による結果の変更はありませんが、
通常実行のFFTと終了判定に起因する変動は、上記の追加調査で再現しています。

## 検証条件を固定した1日分の処理時間

Apple M4 Max、Metalでslant stack、CPUで推定・bootstrap、12スレッド、
2005年3月15日の1日分・3成分で測定しました。帯域・格子は上記と同じです。
各モード1回の慣らしを除外し、3組を交互の順序で新しいプロセスとして実行しました。
OSキャッシュは保持し、ビルドやテストは同時実行していません。
この計測では、上記の検証用実行ファイルを使用し、bootstrap乱数と
`FFTW_ESTIMATE | FFTW_UNALIGNED` を固定しています。

| 1日分の中央値 | all | selected |
|---|---:|---:|
| 全体 | 32.260秒 | 13.252秒 |
| bootstrap段階 | 7.853秒 | 2.809秒 |
| 初期パラメータの格子探索 | 3.050秒 | 1.055秒 |
| 出力行 | 46 | 17 |

全体で **58.92%短縮、2.434倍の速度**でした。測定範囲は31.831–32.406秒と
13.142–13.400秒です。各 `all` 実行は保存済みMetalの46行と一致し、各 `selected`
実行はその選別後17行と全列がバイト単位で一致しています。各組で初期候補数と
採用波形窓も一致しました。bootstrapに加えて推定・行列計算も省略した効果です。
この環境の1日分・3組の比較であり、CUDAでの時間は未測定です。効果は閾値未満の
候補数によって変わります。

`analyze_outputs.py` で共通イベントと欠けたイベントの比較を行います。

そこの `run_check.py` で選別後の全出力と初期候補ログを比較します。

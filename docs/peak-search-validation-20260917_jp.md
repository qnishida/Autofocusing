# ピーク探索の引き継ぎと検証（2026-09-17）

本資料はピーク探索のみを修正した比較を記録する。そこで見つかったNaNへの
[共分散計算の精度修正](parameter-covariance-precision-20260917_jp.md)は別資料に記録し、
元の失敗した実行記録は維持する。

合意済みの初期値選択の修正を、main `485d761` から作成した
`test/peak-search-boundaries` に実装した。実装・回帰テスト・本検証記録を
テストブランチの変更に含める。運用バイナリ、main、
リモートは更新していない。先のバイアス修正は既にmainに入っている。
今回、共分散や収束条件は変更していない。

## 維持した仕様と修正

候補中心の探索円を維持し、背景・局所最大判定には計算済みの正方格子を使う。
探索円外でも計算済みの近傍値は参照する。
ピーク値と周辺平均との差の7×MAD閾値、約0.01 s/kmの近傍幅、候補数上限、
鉛直由来の水平追加候補に対する0.1 s/kmの除外幅は維持した。
周波数に応じた幅の調整は今回の対象外。

- 厳密な局所最大でない候補では、探索全体を終了せず、その候補をスキップする。
  後続全てが閾値に届かない場合の早期終了は維持する。
- 背景参照で両座標の境界を確認し、実際に加算した参照数で平均する。
  内側の候補では加算順序とリング端点の重複した重みを保持する。
- 中心を除き、実際に比較した有効な近傍数で局所最大を判定する。
  近傍の一部が欠けることだけを理由に端の候補を落とさない。
- 旧背景処理の2つ目のループは `dpy_ary[imask] == 0` により常に0回だったため、
  削除しても内側の参照値は変わらない。

## 合成入力・回帰テスト

合成入力25ケースが合格。3成分の中央ピーク、候補数上限、同値ピークの後続にある
孤立ピーク、四方の端とその近傍、円外中心の除外と円外格子の近傍利用、
境界背景の参照数、閾値の上下、近接サイドローブの抑制、検出なし、
±0.4の探索範囲、細かいdpを確認した。
このテストではBoostの配列境界チェックを有効にしている。

旧関数では同値ピークのテストが失敗し、境界だけのテストは範囲外参照で停止する。
修正後は両方合格。影響するターゲットを再ビルドし、関連CTest11件も全て合格した。

## 実データ比較

2005年3月15–17日、CPU・3成分、指定周波数0.1–0.25 Hz、slowness ±0.165 s/km、
dp=0.005 s/km、8スレッド。開始・終了日、波形・震源カタログのハッシュ、採用窓、
bootstrap固定乱数、FFTW ESTIMATE | UNALIGNEDを共通化した。
変更前の出力は保存済みCPUの60イベントをバイト単位で再現した。
候補は最終位置の近さではなく、時間窓・成分・初期slownessで対応付けた。

| 項目 | 変更前 | 修正後 |
|---|---:|---:|
| 初期候補 | 60 | 147 |
| 収束・出力行数 | 60 | 143 |
| 反復上限による不成立 | 0 | 3 |
| line searchで不成立 | 0 | 1 |
| 閾値通過R / T / U | 28 / 10 / 15 | 31 / 10 / 34 |

既存60候補・60イベントは全て保持され、推定パラメータ、反復数、行列とエネルギー比を
含む出力全38列が一致した。追加は87候補で、83件が収束、3件が反復上限、
1件がline searchで不成立。追加分のうち、Rが3件、Uが19件、既存の後処理閾値を通過した。
閾値はR/Tがmax/MAD > 7、Uが > 35。閾値通過は新たな物理イベントの独立な確認ではない。

この実データでは、追加候補の近傍は全て格子内に収まっている（座標の絶対値最大0.144 s/km）。
従って実データの追加分は探索継続と鉛直由来の追加候補への伝播を確認したもので、
端の方針は合成入力で検証した。初期候補の増加自体を不具合とはしない。

## 有限値チェックの失敗：後段の共分散

実データ検証は**無条件の合格ではない**。
追加T候補1件のパラメータ共分散10列（21–30列）が全てNaNになった。
初期値は(0.063,-0.054) s/km、時間窓開始は2005年3月16日11:51:28。
max/MADは-2.70888で、既存の >7 の選別を通らない。
閾値を通過した75行は全て有限値だった。

品質判定の履歴を維持した2日間の対象候補だけの再実行で、この行を完全に再現した。
Hessian/sigmaは有限値だが、単精度の行列式・逆行列は非有限値になった。
倍精度の行列式は約5.20497e39で、floatの最大約3.40282e38を超える。
倍精度の逆行列は有限値だった。
これは共通CPU処理 `est_dist_boot()` の逆行列計算の数値範囲の問題で、
以前確認した共分散の出力スケール規約とは別。新しい初期値で顕在化したもので、
ピーク探索修正は共分散計算を変更していない。
倍精度で有限になること自体は、統計的な誤差評価の妥当性を保証しない。

実行スクリプトの全出力有限チェックは失敗のまま保持し、条件は緩めていない。
比較ツールは失敗した実行も診断できるが、合格と読み替えない。
運用への採用前に、弱い候補で共分散が非有限になる場合の扱いを別の変更として
検討する必要がある。この例を隠すために、合意した初期候補の条件を厳しくしない。

## 再現方法とローカル記録

```bash
cmake -S . -B build-clang -DCMAKE_EXPORT_COMPILE_COMMANDS=ON
cmake --build build-clang --target test_peak_search --parallel 4
ctest --test-dir build-clang -R '^peak_search_boundaries$' --output-on-failure
```

`tests/build_peak_search_probe.py` は既存のローカル検証環境を利用する。冒頭の前提条件を参照。
共分散修正後に当時の比較を再現する場合は、`--source` に保存済みの
`docs/benchmarks/peak-search-boundaries-20260917/peak-only-production.cpp` を渡す。
このソースのハッシュは当初の記録と一致する。
`tests/compare_peak_search_runs.py` は実行ペアを比較し、
追加・消失した候補と失敗した検証項目を保持する。
詳細ログ、カタログ、ソース・ビルドのハッシュ、旧版テストの失敗、共分散の再実行は
`docs/benchmarks/peak-search-boundaries-20260917/` にローカル保存した。
このディレクトリはGitの除外対象で、公開しない。

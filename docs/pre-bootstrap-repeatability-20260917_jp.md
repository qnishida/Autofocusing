# bootstrap前の再現性調査（2026-09-17）

後続作業として[Newton法の単精度版への復元と検証](newton-fp32-rollback-20260917_jp.md)を完了しました。
以下の「本番ソースなどは未変更」という記述は、その復元前の調査時点を示します。

3月15–17日の通常実行で欠けたRイベントについて、bootstrapを呼ばずに棄却を
再現しました。FFT計画による丸め差がNewton推定の終了判定に影響しています。
bootstrap標本の統計的なばらつきではありません。この調査では本番ソース、
インストール済み実行ファイル、設定を変更していません。

## 再現条件

対象は区間開始 `20050317T115128`、初期px/py = −0.01/0.09 s/km、
max/MAD ≈ 24.2705のRイベントです。3日分の波形・QCを元の順序で処理し、
帯域と観測点配置も維持しました。診断ではslant stackを省略し、既に観測された
この初期値からCPUで格子探索とNewton推定だけを行います。bootstrapは呼びません。
採用波形窓は本番と同じ520です。対象区間は47窓、観測点配列は698要素で、
そのうち3成分が揃う観測点は685点です。

最初の1日だけの試行は除外しました。`eval_deri` が窓間の状態を持つため、
前の窓を省くと対象区間が46窓になりました。以下はQC履歴を保った比較です。

| FFT計画 | 独立プロセス数 | Newton推定の戻り値 |
|---|---:|---|
| 本番の `FFTW_MEASURE` | 5 | 4, 4, −1, 4, −1 |
| `FFTW_ESTIMATE \| FFTW_UNALIGNED` | 2 | 4, 4 |

各プロセス内で同じ数値配列から3回推定すると、3回とも同じ戻り値になりました。
4は採用、−1は棄却です。bootstrap呼び出しは全て0回でした。7プロセス全てで
観測点座標、重み、推定初期パラメータはバイト単位で一致しています。
FFT計画を固定した2プロセスでは、スペクトル配列もバイト単位で一致しました。

ログに記録したFFT計画には違いがあり、例えば採用された基準実行には `hf2_32`、
棄却された2実行には `hf_32` が使われています。棄却された2実行の保存スペクトルは
同一です。棄却例と基準例のNewton入力Rスペクトルの差は、
`||R_棄却 − R_基準||₂ / ||R_基準||₂ = 2.6343e−16` でした。
これは数値配列同士の差で、イベント間の分布や推定バイアスではありません。
`FFTW_MEASURE` が実行時の計測で手順を選び、実行間に小さな数値差を生じ得ることは
[FFTW公式FAQ 3.8](https://fftw.org/faq/section3.html)にも記載されています。

## 採否が変わる箇所

4反復目では、両方ともほぼ同じ局所最大点の近くにあり、Hessianの固有値は4つとも
負です。採用例では相対改善量 `+1.65954e−15` の試行が見つかり、厳密な `S1 > S0`
と通常の収束条件を通ります。一方、棄却例では全試行が現在値以下になりました。

| 棄却例の4反復目 | 値 |
|---|---:|
| Newton法による相対改善量の予測 | 2.67668e−16 |
| 実際の最良試行の相対改善量 | −3.68787e−16 |
| 丸め誤差用のパワー許容値（`8 * epsilon`） | 1.77636e−15 |
| 規格化した全Newton更新量の最大絶対値 | 1.64979e−8 |
| 許容される更新量（`sqrt(epsilon)`） | 1.49012e−8 |

丸め誤差用の救済条件は曲率・パワーの検査を通りますが、更新量の上限を約11%超える
ため通りません。改善量の予測が既に丸め限界に達しているのに、戻り値が−1になります。
このため、微小なFFT差がカタログに出るかどうかの差へ拡大しています。

直前の3反復目では、実際の相対パワー増加が `8.816484504155519e−9` でした。
通常の収束条件 `abs(epsilon) < 1e−9` を満たさないため、4反復目へ進みます。
距離パラメータの判定に使う `dprm(2)` は −0.007693775度で、もう一方の既存条件は通ります。
3反復目の増加量は、その更新の前後の差であり、更新後に残る誤差そのものではありません。
3回目の更新で最大点近傍へ進み、次の予測増加は上表の `2.67668e−16` へ小さくなります。
そこで厳密な増加を確認できず、通常の収束判定に進む前にラインサーチ失敗となっています。
後述の旧単精度Newton法も、この入力では3回目ではなく4回目で収束します。

さらに、保存したスペクトル・重み・座標・初期値だけを読み、波形読込、FFT、
格子探索、bootstrapを行わない別実行ファイルでも、採用・棄却をそれぞれ再現しました。
同じ数値入力なら同じ結果であり、FFT出力の差と終了判定の敏感さを確認できます。
元の通常実行ではFFT計画を保存していないため、その実行で使った計画自体を遡って
特定することはできません。この対象候補だけの再実行では他候補を追跡していませんが、
下記の全候補検証で補足しました。
棄却時の戻りパラメータは呼び出し元の格子初期値のままです。最大点付近の値は、
失敗した `#DIAG_RESULT` ではなく `#DIAG_ITER iteration=4` に記録されています。

## 変更前のNewton法との比較

`FFTW_MEASURE` と厳密な `S1 > S0` は初回公開コミット `e551a69` にもあります。
一方、Newton法の4×4演算の倍精度化と `sqrt(eps_double)` を使う追加終了条件は
`dc38340` で導入しました。現在の未コミットの `selected` 変更は、この関数を変更していません。

同じ保存入力2組を、変更直前の `485d761` から取り出したNewton関数、その関数の
`Matrix4f` / `Vector4f` だけを倍精度にした版、現在の版で再計算しました。
旧関数は関数名だけを変更し、目的関数・Hessian集計・初期値・ビルド条件は3方式で
共通にしました。波形読込・FFT・bootstrapは行いません。旧パイプライン全体の再実行ではなく、
Newton法の変更を切り分ける比較です。

| Newton法 | 保存入力 `measure-12-1` | 保存入力 `measure-12-3` |
|---|---|---|
| 変更前：4×4演算は単精度、追加終了条件なし | 採用（4反復） | 採用（4反復） |
| 4×4演算を倍精度化しただけ | 採用（4反復） | 棄却（−1） |
| 現在：倍精度＋追加終了条件 | 採用（4反復） | 棄却（−1） |

このイベントでは、倍精度化によって更新経路・最終反復の丸め方が変わり、既存の厳密な
改善判定との組合せで採否が変わっています。追加条件が新たに棄却しているのではなく、
倍精度化後の失敗をこの例では救済できていません。したがって、今回の変更に伴う
採否の回帰として扱う必要があります。丸め差の発生要因が以前からあることだけを根拠に、
旧版でも同じイベントが不安定だったとは言えません。

当初の3日間比較はFFT計画固定で選別75件の維持を確認しましたが、複数のFFT計画での
再現性は確認していませんでした。保存入力の比較はこの2例に限定され、旧版の全イベントでの
再現性を保証するものでもありません。`run_history.py`、`history-replay.json` とログは
下記のGit管理外の調査ディレクトリに保存しました。本番ソース・実行ファイルは未変更です。

## 全候補の終了状態を追加確認

この問題が対象の1件だけかを調べるため、3月15–17日の全147候補について、
CPUでslant stack・格子探索・Newton法を実行し、全反復の更新量・固有値・予測改善量・
試行パワーを記録しました。bootstrapとカタログ出力は省略し、Newton法の判定は変更して
いません。`ESTIMATE | UNALIGNED` と通常の `MEASURE` を独立プロセスで各1回比較しました。
候補の座標・順序と採用520窓は一致。固定計画の全147戻り値は、以前のbootstrapを含む
全候補検証とも一致しました。棄却された候補だけは、同じ入力で旧Newton法も再実行しました。

| 終了状態 | 固定計画 | MEASURE |
|---|---:|---:|
| 通常収束 | 144 | 140 |
| 追加条件での丸め終了 | 1 | 1 |
| 反復上限 | 2 | 3 |
| ラインサーチ失敗 | 0 | 3 |
| 採用のうちmax/MAD条件を満たすもの | 75 | 74 |

MEASUREのラインサーチ失敗3件は、次のように性質が異なります。

- 既知の3月17日11:51:28のR候補（max/MAD ≈ 24.27）は、予測改善 `2.68e−16`、
  更新ノルム `1.65e−8`、負の固有値4個。旧Newton法は4反復で採用します。
- 3月16日05:55:44のT候補（max/MAD ≈ −2.19）も、予測改善 `2.23e−15`、
  更新ノルム `1.54e−7`、負の固有値4個で、丸め限界に近い停止です。最良試行の相対差は
  `−9.84e−16`。追加条件の更新量と予測改善量の上限を超え、旧Newton法は9反復で採用します。
  この候補は通常のmax/MAD選別では除外されます。
- 3月16日11:51:28の別のT候補（max/MAD ≈ −2.71）は、更新ノルム約0.58、
  正の固有値を1個含み、最良試行でもパワーが約0.41%低下します。上記2例と同じ
  丸め終了として救済する根拠はありません。反復上限3件も更新量・改善量がまだ大きく、
  一律に収束へ変更できません。

固定計画でmax/MAD条件を通った75件のうち、1件は3月16日の丸め救済で、残る通常終了74件の
うち11件は、最後の正の改善量が `8 * eps_double` 以下でした。これは丸めに敏感になり得る
候補の指標であり、11件すべてが誤判定・欠落するという結果ではありません。
ピークごとに曲率・初期値・更新経路が異なり、通常の閾値に達して止まるもの、丸め限界まで
進んでも正の増加を得るもの、追加条件で止まるもの、今回のように棄却されるものがあります。
信頼できるカタログには、十分収束した点の誤棄却と未収束の失敗を区別する終了判定が必要です。
この各1回・3日間の検証から、他期間の欠落率や影響範囲までは推定できません。

追加検証の生成・実行・集計スクリプト、全ログと候補別の記録は
`docs/benchmarks/pre-bootstrap-stop-scan-20260917/`、生成ソースは
`build-clang/pre-bootstrap-stop-scan/` に保存しました（Git管理外）。

## 今後の修正と記録

### 調査時点での推奨方針

後続の依頼で、Newton法だけの復元を検証・適用しました。
[単精度版への復元の検証](newton-fp32-rollback-20260917_jp.md)を参照してください。
本調査中の「未変更」などの記述は、その後続作業より前の状態を示します。

従来の解析を維持しつつ明らかな不具合を修正する目的から、当面の運用候補は
Newton法の4×4演算と終了判定だけを変更前に戻した版とします。共分散逆行列の
倍精度化は、NaNを解消し、単独の3日間比較では共分散以外の出力・採否を維持した
修正なので残します（[共分散の検証](parameter-covariance-precision-20260917_jp.md)）。
バイアス減算、ピーク探索の不具合修正、並列化は別の変更です。コミット全体を戻す
方針ではありません。旧Newton法も、採用前に3日間・複数FFT計画で再確認します。
保存入力2組の一致だけでは、旧版全体の再現性を確認したことにはなりません。

Newton法の倍精度版は別ブランチで終了判定を検証し直します。現在点の勾配・曲率・
全更新量から十分な収束を判断できる場合は、さらに正のパワー増加を得ることを
成功の必須条件にしない設計を検討します。勾配とパラメータ更新の許容値を区別する
考え方は、例えば[SciPy BFGSのgtol/xrtol](https://docs.scipy.org/doc/scipy/reference/optimize.minimize-bfgs.html)
にもありますが、その既定値を今回の問題に流用するものではありません。
許容値は規格化・必要な推定精度から設定し、後述の曲率・パワーの検査も維持します。

倍精度版の採用条件は、既知の採用・棄却入力、鞍点や平坦部の棄却試験、3月15–17日の
複数FFT計画、別期間のデータで確認することです。イベント単位で採否の変化を説明し、
位置・slowness・エネルギー比と `all` / `selected` の共通イベントを比較します。
FFT固定だけで欠落が見えなくなったことや、出力件数だけの一致を完了条件にしません。
本調査の終了時点では提案で、Newton法の復元・別ブランチ作成・本番設定変更は未実施でした。
上記の後続作業でNewton法の復元だけを適用しました。

### 倍精度版の修正候補

丸め限界の改善量に対して一貫した終了判定を行い、同時に鞍点や有意な更新量が残る
状態の棄却を維持する必要があります。保存した採用・棄却の入力を回帰確認に使えます。
FFT計画の固定も再現性の確保に役立ちます。この調査では本番のFFT方針や収束閾値を
変更していません。

### 改善案（未実装）

1. **終了判定を先に見直す。** 実際の更新には改善を要求し、丸め限界では
   現在点を保持して終了できるようにします。負定値Hessian、有限な値、十分小さい
   予測改善量に加え、縮小前の全Newton更新量を各パラメータの許容精度で検査します。
   `sqrt(epsilon)` だけでは必要な推定精度を表せないため、規格化と物理単位での
   更新量を確認して許容値を決めます。今回の1例に合わせた閾値の増加や、
   `S1 > S0` を `S1 >= S0` にするだけの変更は採用しません。鞍点、特異な曲率、
   有意な更新量が残る状態、有意なパワー減少の棄却は維持します。
2. **FFT計画を再利用可能にする。** 同じビルド・実行環境で計画を固定するには、
   検証用の `FFTW_ESTIMATE`、または計測して保存したwisdomの再利用が候補です。
   高速化との両立には後者を評価し、FFT長・種類・配列アラインメント・FFTW版と
   有効な計画を記録します。今回の固定計画試験は `ESTIMATE | UNALIGNED` なので、
   `ESTIMATE` 単独の性能や一致を検証済みとは扱いません。`UNALIGNED` はSIMDを
   制限するため、既定値にする前に計測が必要です
   （[FFTW planner flags](https://fftw.org/doc/Planner-Flags.html)）。
   計画固定は再現性を改善しますが、別環境の丸め差に対する終了判定の検証も必要です。
3. **採否が変わる理由を検証・記録する。** 保存した採用・棄却入力、既存の鞍点・
   平坦部・大更新量などの棄却試験で確認後、3月15–17日を複数計画で再計算します。
   ピーク探索とmax/MAD閾値を維持し、変更されたイベント、位置・slowness・
   エネルギー比、`all` と `selected` の共通イベントを比較します。bootstrap誤差を
   比較する試験では、その乱数も別途固定します。終了理由を通常収束・丸め限界・
   探索失敗・曲率不適合・反復上限に分けると、数値的な棄却を追跡できます。

ビルドスクリプト、7実行のログ、FFT計画、入力差、保存入力の再実行結果は
`docs/benchmarks/pre-bootstrap-repeatability-20260917/` に保存しました。
診断用ソースと数値配列は `build-clang/pre-bootstrap-repeatability/` にあります。
いずれもGit管理外です。`build_probe.py` で診断用バイナリを作り、
`run_probe.py MODE REPEAT [THREADS]` で独立実行を行います。
`run_frozen.py` は記録された採用・棄却のNewton入力を再実行します。
